# Document Consolidator

# Release 1 Scope

Version: 1.0  
Status: Approved Product Scope

---

# Purpose

This document defines the complete scope of Release 1.

It establishes exactly what will and will not be delivered.

The purpose of this document is to prevent scope expansion during development and provide a stable target for Engineering.

Only functionality described within this document forms part of Release 1.

---

# Product Mission

Safely consolidate documentation into a single authoritative document set without risking data loss.

Every capability included within Release 1 must directly support this mission.

---

# Product Philosophy

Release 1 prioritises:

- safety over convenience
- transparency over automation
- deterministic behaviour over intelligent guessing
- user control over automatic decisions
- recoverability over destructive operations

The application intentionally performs one task well rather than attempting to become a general document management solution.

---

# Core Principles

## Local First

Release 1 operates entirely on the local filesystem.

No networking or cloud services are required.

---

## Deterministic

Every recommendation is based upon objective evidence.

Release 1 never attempts to infer user intent using AI.

---

## Non-Destructive

Release 1 never performs destructive filesystem operations.

Existing documents are never overwritten.

Existing documents are never permanently deleted.

Whenever an approved operation would replace an existing document, the application first preserves the existing document before completing the requested action.

Every filesystem operation therefore remains recoverable.

---

## User Controlled

No filesystem modifications occur without explicit user approval.

---

## Transparent

The application clearly explains:

- what it discovered
- why a recommendation exists
- what evidence supports it
- what actions will occur

---

## Verifiable

Every filesystem operation is verified after execution.

---

# Included Functional Scope

Release 1 includes the following capabilities.

---

## Scan

The application shall allow the user to:

- select one or more root folders
- create a Scan Session
- refresh an existing Scan Session
- reopen previous Scan Sessions
- cancel an active scan

Scanning shall never modify the filesystem.

---

## Inventory

The application shall:

- discover supported documentation
- classify discovered documents
- record document metadata
- create an internal inventory
- allow inventory browsing
- allow searching
- allow filtering

---

## Recommendation Engine

Generate deterministic recommendations using agreed evidence.

Recommendation categories:

- Keep
- Move
- Merge
- Review
- Archive

Recommendations must explain the supporting evidence.

Whenever confidence is insufficient, the recommendation shall become **Review**.

---

## Review

Allow the user to:

- inspect recommendations
- inspect supporting evidence
- approve
- reject
- modify
- defer

Nothing is executed during review.

---

## Dry Run

Generate a complete execution preview.

The preview shall identify:

- affected documents
- destination locations
- archived documents
- preserved documents
- proposed filesystem changes

No filesystem changes occur during a dry run.

---

## Execute

Perform approved filesystem operations.

Immediately before execution the application shall:

- validate affected documents
- detect filesystem changes since scanning
- abort execution if validation fails

During execution the application shall:

- perform approved actions
- verify every completed operation
- generate an execution audit

---

## Non-Destructive Execution

Release 1 shall never overwrite an existing document.

Whenever an approved action would replace an existing document, the application shall:

- preserve the existing document
- complete the requested action
- verify both preservation and execution

This behaviour is mandatory for every filesystem operation.

---

## Recovery

The application shall allow the user to recover from previous execution sessions.

Recovery shall include restoration of preserved documents where supported.

Recovery exists because Release 1 preserves documents rather than destroying them.

---

## Audit

The application shall maintain an audit history containing:

- Scan Session identifier
- execution identifier
- execution date and time
- Scan Session date and time
- recommendations
- user approvals
- execution history
- preserved documents
- verification results
- recovery history

---

# Explicitly Excluded

Release 1 intentionally excludes:

## Artificial Intelligence

- AI recommendations
- AI document comparison
- AI document understanding
- AI summarisation
- AI classification

---

## Cloud Services

- cloud storage
- cloud synchronisation
- remote execution
- collaboration

---

## Automation

- scheduled scans
- background monitoring
- automatic execution
- unattended operation

---

## Document Management

Release 1 is not:

- a document editor
- a knowledge management system
- a notes application
- a document repository

---

## Source Code Management

Release 1 does not manage:

- source code
- Git repositories
- build artefacts
- dependency folders

---

## Enterprise Features

Release 1 excludes:

- multi-user support
- authentication
- permissions
- workflow approvals
- administration

---

## Analytics

Release 1 excludes:

- dashboards
- metrics
- trends
- reporting
- productivity analysis

---

# Product Boundaries

The application answers one question:

> "How can I safely consolidate documentation?"

It intentionally does not answer:

- How should projects be organised?
- How should documentation be written?
- How should version control work?
- How should files generally be managed?

Those concerns remain outside Release 1.

---

# Success Criteria

Release 1 will be considered successful if the user can:

- scan documentation across multiple folder trees
- understand the discovered documentation
- identify duplicate or obsolete material
- confidently approve recommendations
- safely consolidate documentation
- preserve replaced documents
- recover previous document states when required

without concern that documents may be lost or existing documents overwritten.

---

# Non-Functional Success Criteria

Release 1 should demonstrate the following qualities.

## Predictable

Behaviour is consistent.

---

## Transparent

Recommendations are understandable.

---

## Safe

Filesystem operations are validated and verified.

---

## Non-Destructive

No filesystem operation permanently destroys user data.

No existing document is overwritten.

---

## Recoverable

Previous document states remain recoverable through preserved documents.

---

## Reliable

Execution results can be trusted.

---

## Simple

The workflow is easy to understand and focused on a single purpose.

---

# Release 1 Exit Criteria

Release 1 is complete when:

- every scoped feature has been implemented
- the complete workflow functions correctly
- Scan Sessions persist correctly
- recommendations operate correctly
- non-destructive execution functions correctly
- preservation of existing documents functions correctly
- recovery functions correctly
- verification succeeds
- audit history is complete

Release 1 is **not** delayed because additional ideas exist.

New ideas belong to future releases unless they are critical to the Release 1 mission.

---

# Guiding Principle

Every design decision for Release 1 should satisfy the following statement:

> **Document Consolidator never performs a destructive filesystem operation. Every significant action is transparent, verifiable, recoverable and remains under the explicit control of the user.**
